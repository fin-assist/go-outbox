# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии и выпуск — [docs/releasing.md](docs/releasing.md). Каждый PR, который меняет API или поведение библиотеки, добавляет строку в «Unreleased»; при выпуске раздел получает номер версии и дату.

## [Unreleased]

### Несовместимо

- FIN-244: `Dispatcher.Run` немедленно возвращает `postgres.ErrForeignTransaction`, если контекст содержит текущую транзакцию go-postgres. Запускайте worker с lifecycle-контекстом сервиса вне callback `Manager.Run`; транзакционный контекст передавайте только операциям сервиса и Publisher. Отказ не запускает горутины и не обращается к pool; повторный запуск с корректным контекстом разрешён.

### Изменено

- FIN-292: миграция `000002` добавляет индекс `outbox_events_lane (target, next_attempt_at, id)` через `CREATE INDEX CONCURRENTLY` (отдельный файл, вне транзакции); индекс `(next_attempt_at, id)` сохранён. Цикл получателя и разложение событий (`target=''`) выбирают кандидатов только своего `target` по новому индексу, поэтому backlog одного получателя больше не читается на каждой доставке остальным. Строки удалённых маршрутов обслуживает отдельный проход: при старте `Run` и раз в 5 минут, пачками вперемешку с fanout. Запрос кандидатов отправляется безымянным выражением, чтобы PostgreSQL не перешёл на generic plan. Совместимо: API и метрики не меняются, код работает и до применения миграции; сервисам после обновления нужно выполнить `migrate up` (источник `outbox`). При падении построения индекса — удалить `INVALID`-индекс и повторить по README.

- FIN-244: транзакции выбора и fanout доставщика выполняются через go-postgres v0.1.2 на одном выделенном соединении; session lock, доставка вне транзакции и сервисная транзакция Publisher сохранены. Контекст чужого Manager отклоняется до SQL и доставки; примеры и тесты проверяют композицию с сервисным Manager.

### Добавлено

- FIN-243: по решению владельца только пакет internal/pgtest исключён из общего Go-списка инструментирования всех трёх уровней; его тесты продолжают выполняться, выбор пакетов и пустой список проверяются регрессионными тестами.

- FIN-243: независимые unit/integration/consumer API пороги statements 80% с закреплённым go-test-coverage, проверкой непустого исполнения и штатными artifacts вместо изменённых строк; приватные интерфейсы pool/connection для независимой проверки владения соединением без изменения публичного API, тесты и регламент проверок.

- FIN-109: transactional Publish, fanout по конфигурации, primary-only worker с LISTEN/poll, безопасные повторы системных gRPC-вызовов, метрики и инструкция внедрения.

- FIN-214: правило Squawk `prefer-bigint-over-int` отключено; ширина целочисленных полей выбирается по диапазону домена.
